# Цифровой паспорт ребёнка — прототип

Прототип архитектуры для кейса SportZania «Единый профиль ребёнка» (SK Kids Challenge 2026).
Все данные синтетические.

## Что есть (шаги плана на 6–11 ноября)

Быстрее всего посмотреть всё сразу: `python demo.py` — год Маши через все механизмы паспорта.

## Запуск проверок

```bash
pip install -r requirements.txt
python -m pytest -q

python demo.py                                # сквозной сценарий Маши

python -m generator.generate                  # 200 детей через весь конвейер, сводка
python load_estimate.py                       # нагрузка по умолчанию
python load_estimate.py --concurrent 10000    # все дети одновременно

# схема на PostgreSQL 14+
psql -v ON_ERROR_STOP=1 -f schema/ddl.sql -f schema/smoke_test.sql
```

## Упрощения прототипа

* Хранилище в памяти вместо PostgreSQL, вызовы функций вместо RabbitMQ.
* Ключи эмитентов выводятся из фиксированного seed (только для воспроизводимого демо), в проде — KMS/HSM.
* DID эмитента не резолвится по сети: открытые ключи берутся из реестра эмитентов (`passport.issuer.public_key`).
* Подписывается JSON бейджа как есть, без JSON-LD-канонизации (так допускает VC-JWT).
